STAFF & PAYROLL (HR) MODULE — BUILD ROADMAP
Inventory Management System / Glory Desk
============================================

Status: PHASE 6 DONE (2026-08-16). Phases 7-10 not started. This file tracks
the build, phase by phase, the same way industry-roadmap.txt tracks the rest
of the product. Mark [x] only when a task is actually working end-to-end, not
when it's "mostly done" — that's how industry-roadmap.txt ended up claiming
things (mobile apps, SSO, SMS) that don't really work.

Conventions used throughout: Entity -> Service -> ViewModel -> View -> DI
wiring in App.axaml.cs -> nav entry + permission + license gate in
MainViewModel.cs -> tests -> docs. Copy an existing module (Suppliers is the
closest analogue) rather than inventing a new pattern.

Decisions baked into this plan — revisit if you disagree:
- Employee is its own entity, separate from User (login account). Staff who
  never log into Glory Desk (cleaners, drivers) still need payroll records.
  Employee has an optional UserId link for staff who also log in.
- Statutory numbers (PAYE bands, RSSB %, CBHI %) are editable settings, not
  hardcoded — rates change, and you may sell outside Rwanda later.
- License gating: Staff records at Medium+, Payroll processing at Pro+
  (matches how Forecasting/Audit Trail are gated today). Change if you want
  Payroll to be an Enterprise-only upsell instead.
